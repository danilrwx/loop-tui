# Управление Loop TUI

## Клавиши

| Клавиши | Действие |
| --- | --- |
| `j` / `k`, `↑` / `↓` | В списке перейти к соседнему чату. В ленте прокрутить длинное сообщение на строку или перейти к соседнему посту |
| `J` / `K` | Сразу перейти к соседнему посту |
| `Ctrl+U` / `Ctrl+D`, `PgUp` / `PgDn` | Прокрутить на полстраницы или страницу. Если сообщение не влезает, сначала прокручивается его текст |
| `l` / `Enter` | Открыть выбранный чат |
| `/`, `Ctrl+K` | Поиск каналов и людей по имени или `@username`. Для вступления в новый канал нужно подтверждение |
| `?`, `Ctrl+F` | Поиск сообщений в текущем чате или по всем чатам. `Tab` меняет область поиска, `Enter` ищет или открывает сообщение |
| `f` | В «Discussions» переключить отслеживаемые, непрочитанные и свои треды. В «Mentions & reactions» переключить упоминания и реакции |
| `w`, `W` | Подписаться на выбранный тред или отписаться от него |
| `d` / `c` | Переключить режим личек / каналов в списке чатов |
| `S` | Настройки интерфейса и уведомлений. Пункты `Avatars` и `Hide chat list when open` управляют аватарками и списком чатов |
| `N` | Включить или выключить уведомления обо всех сообщениях выбранного чата |
| `Ctrl+N` / `Ctrl+P` | Перейти в соседний чат |
| `t` / `Enter` | Открыть тред выбранного сообщения |
| `n` | Открыть следующий непрочитанный тред. В канале — внутри этого канала, в Discussions — по всем каналам. В ручном режиме обходит непрочитанные треды по кругу |
| `u` | Список непрочитанных тредов с началом сообщения и числом новых ответов. `j` / `k` выбирают, `Enter` открывает, `Esc` закрывает список |
| `r` | Начать ответ в треде |
| `i` | Написать в текущем канале или треде |
| `a`, `Alt+A` при вводе | Открыть файловый пикер. Стрелки выбирают, `Tab` дополняет путь, `Enter` открывает папку или прикрепляет файл |
| `Ctrl+V` | Вставить текст или прикрепить PNG из буфера обмена |
| `Ctrl+O` | Вложения черновика. `Enter` открывает файл, `e` редактирует копию в редакторе, `d` убирает вложение |
| `V` | Вложения из загруженной истории канала или треда |
| `Alt+T`, `Ctrl+T` в пикере | Задать имя и расширение текстового вложения, затем открыть черновик в редакторе. Имя по умолчанию — `message.txt` |
| `Ctrl+X` | Открыть текущий черновик в редакторе |
| `@имя`, `↑` / `↓`, `Tab` | Найти коллегу и вставить его ник |
| `Ctrl+J`, `Enter` | Добавить строку, отправить сообщение |
| `v` | Открыть сообщение на весь экран. `Ctrl+U/D` листает, `g` / `G` переходит к началу или концу |
| `F` | Развернуть активный чат или тред на весь экран или вернуть панели |
| `x` | Развернуть или свернуть длинные поля таблиц в выбранном сообщении |
| `z`, `1`–`9` | Поставить несколько реакций подряд. `7` — 🔙, `8` — ✅, `9` — 👀. Повторный выбор снимает реакцию, `Esc` закрывает меню |
| `z`, `←` / `→`, `Enter` | Выбрать и добавить реакцию, которая уже стоит у кого-то на сообщении |
| `z`, `Tab` | Открыть поиск по каталогу эмодзи Loop. `↑` / `↓` выбирают, `Enter` ставит либо снимает реакцию |
| `D` | Удалить своё сообщение. `y` подтверждает удаление, `Esc` отменяет |
| `o`, `O` | `o` открывает фото крупнее. `O` показывает ссылки и вложения сообщения |
| `m`, `R` | Отметить канал или открытый тред прочитанным, обновить данные |
| `Tab`, `h` / `Esc`, `q` | Сменить панель, вернуться, выйти |

В `S` → `Mark read` выберите `Only m`, чтобы открытие канала или треда не сбрасывало непрочитанность. В этом режиме только `m` отправляет отметку прочтения, и лишь после успешного ответа сервера клиент убирает счётчик. Для треда `m` отмечает прочитанным только содержимое, которое уже загружено; более новые ответы остаются непрочитанными. `On open` сохраняет автоматическую отметку при открытии. Для существующих настроек без этого поля действует прежний режим `On open`.

Клиент обновляет открытый канал и тред каждые пять секунд, список дискуссий — каждые 15 секунд. Число рядом с Discussions показывает количество непрочитанных тредов во всех каналах. Если окно узкое, тред занимает область переписки.

Избранные чаты показаны сверху в том же порядке, что и в веб-Loop. Цвета интерфейса берутся из ANSI-палитры терминала. При её смене открытый интерфейс меняет цвета сразу, без перезапуска клиента.

Непрочитанные чаты выделены точкой и счётчиком. `@3` означает три упоминания, `↳2` — два новых ответа в отслеживаемых тредах. Точка рядом со временем выделяет новые сообщения в открытой ленте.
Строка `↓ N unread chats` показывает, сколько непрочитанных чатов осталось ниже видимой части списка.
Клавиши `d` и `c` независимо переключают лички и каналы между всеми чатами и только непрочитанными. Избранное видно в обоих режимах. По умолчанию лички открываются в режиме «непрочитанные». Поиск `/` находит чаты во всех группах и запрашивает каталог Loop. Редактор выбирается в порядке `$VISUAL` → `$EDITOR` → `vim`. В настройках `h` / `l` меняют ширину, `0` возвращает автоматическую, `Enter` меняет режим выбранной группы. Ширина хранится в общей настройке `chat-tui/settings.json` и применяется в telega при запуске.

Markdown-ссылки отображаются одной подписью. В меню `o` доступен исходный адрес. Вложения загружаются в локальный кэш и открываются системным просмотрщиком.

Поле ввода видно в открытом канале и треде. Оно растёт до половины окна и прокручивается внутри, когда строки перестают помещаться. `Esc` возвращает к навигации и сохраняет текст. Черновик хранится на этом компьютере и восстанавливается при повторном открытии чата или треда.

В каналах и тредах цвет ника зависит от ID пользователя. Он сохраняется после перезапуска и смены имени.

При реализации сверялись с [mmux](https://github.com/iRootPro/mmux), в частности с фильтрацией ответов из ленты и загрузкой треда по ID корневого сообщения.

С Kitty или Sixel миниатюры вложенных изображений видны под сообщениями, а пользовательские реакции со статической картинкой отображаются рядом со счётчиком. Если при запуске терминал ещё не поддерживал графику, клиент повторяет проверку в фоне и включает аватарки и миниатюры в том же окне. `R` заново проверяет графику и повторяет загрузку изображений, в том числе после временной ошибки. Нажмите `o`, чтобы открыть фото крупнее. Перед открытием клиент заново проверяет поддержку графики в tmux: результат не застревает на терминале, который был подключён при запуске. Повторное `o` открывает фото в системном просмотрщике. Если встроенный просмотр не поддерживает формат или размер изображения, используется системный просмотрщик. В пикере `z` → `Tab` клавиша `Ctrl+O` показывает картинку выбранного пользовательского эмодзи. `Esc` закрывает просмотр.

## Уведомления

Для системных уведомлений нужен `notify-send`. Loop TUI уведомляет о новых личных и командных упоминаниях, а также об ответах в подписанных тредах. Получателей упоминаний и список подписчиков определяет сервер Loop, как для веб-клиента. Уведомления повторяются раз в минуту. Для ответов без упоминания в подписанных тредах повторы останавливаются после прочтения. В `S` → `Mention reminders` выберите, когда останавливать повторы для остальных упоминаний: после прочтения, после вашей 👀 или после любой вашей реакции на сообщение.

На Linux установочный скрипт автоматически устанавливает и включает пользовательский сервис `loop-tui-notifications.service`. Он запускает `loopd` с тем же аккаунтом и настройками, поэтому уведомления продолжают приходить после закрытия интерфейса. При повторной установке скрипт обновляет unit-файл; путь запуска учитывает `LOOP_INSTALL_DIR`. Существующий SSO-лаунчер в `~/.local/bin/loop` с бинарником в `~/.local/libexec/loop` сохраняется.

Если пользовательский `systemd` недоступен при установке, скрипт сохраняет unit-файл и выводит команды для его включения после входа в систему. На macOS и OpenBSD сервис systemd не устанавливается. Старые релизы без отдельного демона устанавливаются без сервиса.

При установке из исходников или архива сервис можно включить вручную:

```sh
./loop --install-notification-service "$PWD/loopd"
```

Для сервиса нужен неинтерактивный вход: `LOOP_SERVER` и `LOOP_TOKEN` в окружении user-сервиса либо существующая SSO-конфигурация `~/.config/matterhorn/config.ini` (`host` и `tokencmd` в секции `mattermost`). Оба бинарника читают её напрямую; отдельный SSO-лаунчер больше не требуется. Токен не нужно указывать в unit-файле. Статус: `systemctl --user status loop-tui-notifications.service`.

Уведомления отправляет отдельный `loopd`; интерфейс их не дублирует. Блокировка не позволяет одновременно запустить два демона для одного аккаунта. Демон не загружает переписки, аватары, графику, каталог эмодзи или редактор. В памяти хранит небольшую очередь событий, короткие выдержки из ожидающих сообщений и счётчики непрочитанного. Очередь сохраняется в закрытом для других пользователей каталоге `$XDG_CONFIG_HOME/loop-tui/notifications` (по умолчанию `~/.config`). После перезапуска сервис восстанавливает очередь и перепроверяет прочтение и реакции. При потере истории WebSocket он сверяется с серверными счётчиками и сообщает о пропущенных упоминаниях и ответах сводным уведомлением. После сбоя уведомление может повториться. При замене бинарника сервис автоматически перезапускается. В unit-файле заданы `GOMEMLIMIT=8MiB`, `GOGC=50` и `GOMAXPROCS=2`: это уменьшает удерживаемую память и число потоков. `GOMEMLIMIT` — мягкий бюджет Go, а не ограничение RSS; при большой очереди процесс может использовать больше памяти.

Нажмите `N` на выбранном чате, чтобы получать уведомления о каждом новом сообщении и ответе в треде. В списке рядом с таким чатом появляется `♢`. Режим хранится локально для конкретного чата. В нём напоминания останавливаются после прочтения, включая сообщения с упоминаниями. При `Mark read` → `On open` открытие канала или треда отмечает сообщения прочитанными. В режиме `Only m` нажмите `m` после прочтения. Прочтение в веб-Loop учитывается, если сервер сохранил его для канала или треда.

Графика включается автоматически в Kitty и Foot. Для другого терминала с поддержкой Sixel запустите клиент с `TUI_GRAPHICS=sixel`. `TUI_GRAPHICS=off` отключает графику. В tmux автоматический выбор Sixel требует поддержки Sixel в сборке tmux и на внешнем терминале. В Foot настройки tmux `set -g allow-passthrough on` и `set -g focus-events on` позволяют передавать встроенные картинки прямо терминалу, обходя малый Sixel-кэш tmux. При возврате в панель клиент восстанавливает картинки.

## Обновления

Релизная сборка проверяет новые версии в фоне при запуске. В диалоге можно выбрать **Install update**, **Later** или **Don't show again**. Later откладывает предложение до следующего запуска. Don't show again отключает автоматические предложения. Демо и dev-сборки не проверяют обновления.

Клиент проверяет SHA-256 архива и версии обоих бинарников: `loop` и `loopd`. Затем обновляется установленный unit-файл из шаблона, встроенного в новый проверенный `loop`. Путь запуска сохраняется; старый запуск `loop-tui --notify` переводится на соседний `loopd`. Выполняется `daemon-reload`, работающий сервис перезапускается. Выключенный или остановленный сервис обновление не включает и не запускает. Интерфейс нужно перезапустить вручную. При ошибке скачивания или проверки прежние бинарники сохраняются. Если бинарники уже заменены, а настройка сервиса не удалась, клиент сообщает об этом отдельно.

Ручная проверка и установка работают и после отключения предложений:

```sh
loop --check-update
loop --update
```
